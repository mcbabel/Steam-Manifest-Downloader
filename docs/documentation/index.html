01 Getting started

three parts

Getting started #

Steam Manifest Downloader (SMD) is a Tauri v2 desktop application built with Rust and a WebView front end.

In this section

  • System requirements
  • Installation
  • First launch

It walks you through five steps:

  1. Parse a .lua or .st file, or search by Steam App ID across your configured sources
  2. Pick the depots you want, with platform, architecture and language tags pulled live from Steam's PICS info
  3. Download the selected depots with the native Rust engine, straight from Steam's CDN
  4. Optionally create desktop and start menu shortcuts (Windows), or add the game to your Steam library with grid art (Linux and Windows)
  5. Optionally patch the game with the gbe_fork emulator so it runs without the Steam client, including DRM detection via Steamless and an API check bypass

System requirements #

  • .net 9 .NET 9.0 Desktop Runtime, Windows, optional. Only needed if you switch Settings, Download engine back to the legacy DepotDownloaderMod path. The default native engine is pure Rust and needs no runtime. Download the .NET 9.0 Desktop Runtime
  • mono Mono, Linux, optional. Only needed if you want to use the DRM removal in step 5, since Steamless is a .NET Framework tool: pacman -S mono or apt install mono-runtime
  • windows Windows 10 version 1803 or later, with WebView2. Windows 11 is supported as well.
  • linux Most modern distributions with GTK3 and WebKit2GTK. For the AppImage: FUSE support, or APPIMAGE_EXTRACT_AND_RUN=1
  • network An internet connection is required for searching and downloading manifests.
  • disk About 20 MB for the app itself, plus space for the depots you download.

Installation #

Windows, NSIS installer #

  1. Download the latest .exe installer from the releases page
  2. Run the installer and follow the setup wizard
  3. Launch Steam Manifest Downloader from your start menu or desktop

Linux, AppImage #

  1. Download the latest .AppImage file from the releases page
  2. Make it executable, then run it

bash

chmod +x SteamManifestDownloader_*.AppImage
./SteamManifestDownloader_*.AppImage

Note

If FUSE is not available on your system, you can run the AppImage with the environment variable APPIMAGE_EXTRACT_AND_RUN=1 set.

First launch #

The very first time you start SMD, two small prompts appear before the main interface:

  1. Language picker. Pick between English and German. Before you make the choice the interface is already localised from your OS or browser language, so a German system starts in German, and if neither matches, English is the fallback. The picker just lets you override that. It is saved immediately, and you can change it later under Settings, Language, where a restart prompt appears so the new translation applies cleanly.
  2. Anonymous telemetry consent. Opt in or decline. Telemetry counters are end to end encrypted with an embedded public key, and you can change your choice anytime under Settings, Advanced settings.

If you installed a build with the bundled archive.org sources, which is the default for the GitHub, installer and AUR source builds, two depot source URLs are seeded automatically so search works out of the box. The Flatpak build does not seed them, so there you need to add at least one source manually under Settings, Advanced settings, Manifest sources.

After the prompts the main interface is ready. Optional next steps:

  • Set a custom download location on the download page (step 3) before your first download
  • Configure a ManifestHub API key on the download page for additional manifest sources
  • Open Settings, Advanced settings to tune the retry count, speed limit or proxy, or to add and remove depot sources

02 Usage guide

five steps

Usage guide #

The pipeline has five steps. Steps 1 to 3, upload, select and download, are always required. Step 4, shortcuts and Steam library, and step 5, the emulator patch, are optional and only appear when they are relevant for your platform and game.

In this section

  • Step 1: upload a file
  • Step 2: select manifests
  • Step 3: download
  • Step 4: shortcuts and Steam library
  • Step 5: emulator
  • Cancel a download

Step 1: upload a file #

Start by providing a manifest data file. You can either:

  • Drag and drop a .lua or .st file onto the upload area
  • Click the upload area to open a file picker

The file picker filters on those two extensions, and anything else is turned away with the message Please select a .lua or .st file.

The application then parses the file and extracts all depot IDs, manifest IDs, app IDs and depot keys contained within.

Tip

You can upload multiple files. Each new upload merges its data with any previously loaded depots.

Step 2: select manifests #

After parsing, the app displays a list of all discovered depots and their manifest IDs. From here you can:

  • Select and deselect individual depots using the checkboxes
  • Use Select all or Deselect all for bulk actions
  • Search and filter depots by ID or name using the search bar
  • View app details fetched from the Steam Store API, such as the game name and icon

Each depot entry shows the depot ID, the associated manifest ID, whether a depot key was found, and a row of metadata tags pulled live from Steam's PICS info via api.steamcmd.net:

  • OS tag, Windows, Linux or macOS
  • Arch tag, 32-bit or 64-bit
  • Language tag, only shown for language specific depots, for example German or French

The metadata is cached per app ID for 7 days in your app data directory, so later visits are instant. If api.steamcmd.net is unreachable the tags simply do not appear, and the rest of the interface is unaffected.

How sources are asked

The search asks your configured depot sources in the order you set. The check for whether an App ID exists stops at the first source that answers, so the order you choose is the order that decides which source supplies the depots, keys and sizes.

Step 3: download #

Click the Download button to begin. Behind the scenes the application performs several operations:

  1. Steam session. Signs in to Steam anonymously and pulls app and depot metadata via PICS
  2. Manifest fetch. Requests each depot's manifest from Steam directly. If that fails, SMD falls back to your configured depot sources or Hubcap, then to the ManifestHub API if you have a key set
  3. Manifest decode. Unwraps the ZIP container, decrypts with AES-256 and parses the protobuf payload, encrypted filenames included
  4. Depot keys generation. Creates a steam.keys file containing all known depot decryption keys
  5. Chunk download. Keeps up to 32 chunk fetches in flight against Steam's CDN, decodes VZ1 (LZMA) or VSZTD (zstd) payloads and verifies each one against its CRC32 and SHA-1 before writing. Failed chunks retry up to 8 times with exponential backoff, rotating CDN servers between attempts

Chunks that already match on disk are verified and skipped, so a restarted download picks up where it left off instead of starting over.

Engines

This is the native engine and it is the default. If you switch Settings, Download engine back to DepotDownloaderMod, SMD instead collects the manifests and hands them to the embedded DDM binary, which requires the .NET runtime on Windows.

You will see real time progress tracking with:

  • A progress bar showing overall completion
  • Download speed in MB/s
  • ETA estimates
  • Per depot status updates

Where files land

The downloaded files are saved to your configured download location, by default Documents/SteamDownloads. Each download creates a subdirectory named after the app ID.

When the download succeeds the app automatically progresses to step 4, or to step 5 on Linux without Steam installed. The history entry is only persisted once you reach Go to home, so closing the app mid flow leaves no trace.

Step 4: shortcuts and Steam library, optional #

Step 4 has two platform specific variants. SMD picks the right one automatically based on whether you are on Windows or Linux and whether Steam is detected.

Windows: create desktop and start menu shortcuts #

The app scans the download folder for executables, scores them by size and by name match against the folder hint, against a blacklist of installers and redistributables, and suggests the most likely game executable. You can:

  • Browse manually for the .exe if auto detection picked the wrong one
  • Toggle Desktop shortcut and Start menu shortcut independently
  • Toggle Also add to Steam library to chain the Steam integration, described in the next part

Shortcuts are created via PowerShell using the WScript.Shell COM object, with user derived values passed through environment variables, so there is no string interpolation and no script injection.

Linux: add to Steam library #

The app detects your Steam installation, at ~/.steam/steam/, ~/.local/share/Steam/ or the Flatpak path, and the active user, via the MostRecent=1 flag in loginusers.vdf. When you click Add to Steam it will:

  1. Download the banner, hero, logo and icon images from the Steam CDN, using the icon hash from api.steamcmd.net
  2. Save them into ~/.steam/steam/userdata/<user>/config/grid/ with the naming Steam expects: <shortcutid>.jpg, <shortcutid>p.jpg, <shortcutid>_hero.jpg, <shortcutid>_logo.png and <shortcutid>_icon.jpg
  3. Parse the existing binary shortcuts.vdf file, with a backup, append a new shortcut entry, and write it back
  4. Generate the shortcut AppID as CRC32(exe_path + app_name) | 0x80000000, which is Steam compatible and deterministic

The Linux step also supports launch options, for example %command%, and a display name field. After adding, restart Steam fully, by right clicking the tray icon and choosing Exit, for the new entry to appear. For Windows games on Linux: right click the new entry in Steam, open Properties, then Compatibility, then enable Proton.

Footer buttons are minimal: Skip proceeds without adding, and Add to Steam switches to a single Next button after success.

Step 5: emulator, optional #

Step 5 patches the game with the gbe_fork Steam emulator so it can run without the Steam client. The whole feature is bundled, with no manual setup. It only appears when the app finds steam_api*.dll on Windows or libsteam_api.so on Linux in the download folder.

Variant picker #

Two gbe_fork variants are offered side by side:

  • Regular, the stable build, recommended for most games
  • Experimental, newer features, may be unstable

The chosen variant's DLL is fetched from the latest gbe_fork GitHub release, extracted into the app data cache at $APP_DATA/gbe_fork_cache/<release-tag>/ and copied over the game's steam_api*.dll. The original is backed up as steam_api*.dll.steam.bak. steam_interfaces.txt is generated natively in Rust by pattern matching against 37 known Steam interface names, so no external generate_interfaces.exe is required.

DRM detection and removal, via Steamless #

Before applying the emulator, SMD scans the game folder for executables protected by Steam DRM (SteamStub). Detection is a fast PE header scan looking for a .bind section, with no execution required.

If DRM is found, a yellow warning banner appears with the affected files. Clicking Remove DRM (via Steamless):

  • Downloads Steamless v3.1.0.5 once into the app data cache
  • On Windows: runs Steamless.CLI.exe directly
  • On Linux: runs it via mono, installed with pacman -S mono or apt install mono-runtime, and MONO_PATH is set to the Plugins/ directory so plugin assemblies resolve correctly
  • Replaces the original .exe with the unpacked version and keeps the original as .exe.drm.bak

The full Steamless log is shown inline if anything fails, with a one-click copy button.

Steam API check bypass, optional toggle #

Some games perform additional integrity or size checks on steam_api*.dll at runtime, and those reject the gbe_fork swap even when it loaded. Enabling the bypass toggle installs Steam-API-Check-Bypass alongside gbe_fork:

  • The matching arch DLL, x64 for steam_api64.dll and x32 for steam_api.dll, is copied next to game.exe under three hijack names: version.dll, winmm.dll and winhttp.dll. Whichever the game imports gets loaded, and the others sit harmless
  • A SteamAPICheckBypass.json file is written next to game.exe with a file_redirect rule that points the first 3 CreateFile reads of steam_api*.dll to the .steam.bak file gbe_fork created, so integrity checks see the original bytes while the game uses the emulator
  • Any pre-existing version.dll, winmm.dll or winhttp.dll is backed up as <name>.bypass.bak and restored on revert

The bypass is only relevant for Windows games. Linux libsteam_api.so targets are skipped automatically.

The 21 emulator settings, in an accordion #

Below the variant picker is a collapsible accordion with 5 sections of tunable gbe_fork options. Only fields you actually fill in are written to disk, and the rest stays at gbe_fork's defaults. The values are saved to localStorage and pre-filled on your next visit.

  • Account, display name, 64-bit Steam ID, game language, IP country (ISO 3166-1)
  • Saves, local save path, per game folder name
  • Network and compatibility, offline mode, Steam Deck mode, disable networking, disable LAN only
  • Stats and achievements, record playtime, achievements bypass, force SteamHTTP success, Steam pre-owned IDs, free weekend flag
  • Overlay, enable the experimental overlay, hide popups, always show FPS and playtime, hotkey, font size

Settings are written as INI files, configs.user.ini, configs.main.ini and configs.overlay.ini, into a steam_settings/ folder next to the patched DLL, alongside steam_interfaces.txt, steam_appid.txt and installed_app_ids.txt.

History actions, per game #

After applying, the game appears in your download history, reachable via Go to home, with an extra action button:

  • Edit emulator settings, the gear button, re-opens step 5 in edit mode. The variant picker is hidden, the accordion is populated from the existing INI files, the Apply button becomes Save settings and a red Revert patch button appears. Reverting restores the original DLL, deletes steam_settings/ and is gated by a confirmation modal

If you delete the game folder externally, the Edit action shows an inline error banner in the history modal instead of crashing.

Cancel a download #

You can cancel an in-progress download at any time by clicking the Cancel button. When a download is cancelled:

  • All in-flight chunk downloads stop immediately, and queued chunks bail out without waiting for a slot. On the DepotDownloaderMod path, the DDM process is terminated instead
  • Partially downloaded files are deleted to avoid incomplete or corrupted data, unless you enabled Keep downloaded files when cancelling in Settings
  • The interface returns to the selection screen so you can start a new download

Careful

By default, cancelling a download deletes all partially downloaded files for that session. Turn on Cancel behaviour, Keep downloaded files when cancelling if you would rather resume later. The job then lands in your history as Resumable, with a Resume button.

03 File formats

two inputs

Supported file formats #

SMD accepts two input files, .lua and .st. A third format, key.vdf, is not something you drop in: SMD reads it from a configured depot source during a search.

In this section

  • .lua files
  • .st files
  • key.vdf from a depot source

.lua files #

Lua script files are the most common format. They contain function calls that define app IDs, depot keys and manifest IDs. The parser recognises the following patterns:

lua

-- Register an app ID (no depot key)
addappid(1995890)

-- Register a depot with a hex decryption key
addappid(1995891, 0, "a1b2c3d4e5f6...")

-- Set the manifest ID for a depot
setManifestid(1995891, "3438272076824159257")
  • addappid(depotId) registers a depot ID
  • addappid(depotId, 0, "hexKey") registers a depot with a decryption key
  • setManifestid(depotId, "manifestId") associates a manifest ID with a depot
  • setManifestid(depotId, "manifestId", sizeBytes) is the same as above plus an explicit install size hint. SMD picks up the size and shows it next to the depot in step 2 if no .json sidecar is present

lua, 3-arg variant with size

-- 3-arg setManifestid carries the install size in bytes
setManifestid(1392863, "4398981003384795747", 13789896785)

.st files #

The .st format is a binary file format used by certain sources. SMD includes a dedicated binary parser that can read and extract depot IDs, manifest IDs and depot keys from these files.

Note

.st files are detected automatically by their binary signature. Drag and drop them like any other supported file.

key.vdf from a depot source #

Valve Data Format (VDF) files use a nested key and value structure. The key.vdf file that SMD fetches from a configured depot source holds depot keys in the following shape:

vdf

"depots"
{
    "1995891"
    {
        "DecryptionKey"    "a1b2c3d4e5f6..."
    }
    "1995892"
    {
        "DecryptionKey"    "f6e5d4c3b2a1..."
    }
}

The parser extracts each depot ID and its associated decryption key from the VDF structure.

Not an input format

A .vdf file cannot be dropped into the app. The file picker filters on .lua and .st only, and anything else is rejected with the message Please select a .lua or .st file. key.vdf reaches SMD only through a configured depot source.

04 Configuration

settings

Settings and configuration #

Open the settings modal via the gear icon in the header. All values are persisted to the app's settings file between sessions.

In this section

  • Top level settings
  • Advanced settings
  • Download page options
  • Emulator settings persistence

Emulator specific settings live in step 5, see Step 5: emulator, and are remembered in localStorage.

Top level settings #

  • Language, the interface language. English and German are bundled, and the picker also runs on first launch
  • Auto-update, toggles whether SMD checks GitHub for new releases on startup and offers an in-app update prompt

Advanced settings, collapsible #

Click Advanced settings to expand the section. It contains the following.

Download engine #

Download directly from Steam (native, recommended) is on by default: an anonymous Steam login fetches manifests and chunks from Steam's CDN in process, with ManifestHub only as a fallback. Turn it off to force the legacy DepotDownloaderMod path, which needs the .NET runtime on Windows.

Cancel behaviour #

Keep downloaded files when cancelling is off by default. Enable it and cancelling leaves the partial files on disk. The job appears in your history as Resumable, and restarting it skips every chunk that already verifies.

DepotDownloader arguments, DepotDownloaderMod path only #

  • Extra arguments, appended verbatim to the DepotDownloaderMod CLI. The internal default is -max-downloads 8 -verify-all, and your input is added on top
  • Max retries on error, how often a failed depot is retried before SMD gives up
  • Download speed limit (MB/s), an optional global cap
  • HTTP proxy, a proxy URL forwarded to DepotDownloaderMod for environments that require one

Manifest sources #

The list of depot sources searched in step 2. Add a URL, with the format auto detected as a GitHub repo, an archive.org item or a plain HTTPS folder, and click Add. Remove one with its close button. Sources installed by the app are tracked separately, so removing a default source triggers a confirmation modal warning that Search by App ID will stop working. Adding the same URL again clears that warning.

API keys, optional #

  • Hubcap API key, when set, Hubcap shows up as a selectable App ID manifest source whenever it has data for the app you searched
  • Ryuu API key, the same for Ryuu

The ManifestHub key is separate and lives on the download page, see ManifestHub API key under Download page options below.

Notification sound #

Toggles a short system notification sound when a download completes. This is separate from the OS desktop notification itself.

Anonymous telemetry, opt in #

SMD can send anonymous usage counters, meaning which features get used, to the maintainer's server to help prioritise development. Events are end to end encrypted with an embedded public key, so only the maintainer's server can decrypt them. It is disabled by default, the choice is asked on first launch, and it can be changed here anytime. Never sent: game IDs, depot IDs, file contents, IP addresses, account info.

Download page options #

These options appear on the download page, step 3, just above the download button.

Download location #

Where downloaded depot files are saved. The default is Documents/SteamDownloads inside your home folder. Each download creates a subdirectory named after the app ID, and the path is remembered between sessions.

ManifestHub API key, optional #

If you have a ManifestHub API key, paste it here. With the native engine it acts as the last fallback, used only when neither Steam directly nor your configured depot sources can supply a manifest. It is also required if you enter a custom manifest ID by hand.

Emulator settings persistence #

The 21 emulator options in step 5, such as display name, language, offline mode and the overlay tweaks, are not stored in the global settings file. Instead they are saved to the browser's localStorage after each successful Apply and pre-filled the next time you reach step 5. Settings opened via history, in edit mode, read live from the game's steam_settings/ INI files instead.

05 Configuration

order decides

Manifest sources #

SMD lets you plug in any number of depot sources under Settings, Advanced settings, Manifest sources.

In this section

  • Supported source formats
  • What gets fetched
  • Depot metadata

Every search asks those sources in the order you set. The check for whether an App ID exists stops at the first source that answers, so the order you choose is the order that decides.

Supported source formats #

  • GitHub repos, auto detected from https://github.com/<owner>/<repo> URLs and fetched via the Contents API with a branches/<appid>/ layout
  • archive.org items, detected from archive.org/download/... or view_archive.php?file=... URLs. SMD treats the zip's basename as a path prefix automatically
  • Plain HTTPS folders, any base URL that serves <appid>.lua, key.vdf, <appid>.json and <depot>_<manifest>.manifest files

What gets fetched #

For each app ID, SMD fetches and merges the following files from the source that answers:

  • <appid>.lua, depot IDs, manifest IDs, depot keys and optional install size hints
  • key.vdf, additional depot decryption keys
  • <appid>.json, depot manifest metadata plus per manifest install and download sizes
  • <depot>_<manifest>.manifest, the actual manifest payload, only downloaded for the depots you select

GitHub rate limit

The GitHub API has rate limits, and unauthenticated requests are capped at 60 per hour per IP. SMD does not ship a token field for this. If you hit the cap, wait an hour or add a different source, such as archive.org or a plain HTTPS folder, which has no such limit.

Depot metadata, the step 2 tags #

Independent of the manifest sources, SMD queries the public Steam PICS mirror at api.steamcmd.net/v1/info/<appid> to render the OS, arch and language tags shown next to each depot in step 2. Results are cached per app ID for 7 days in $APP_DATA/depot_info_cache/.

06 Development

Building from source #

This guide covers how to compile Steam Manifest Downloader from source. The project uses Tauri v2 with a Rust backend and an embedded .NET tool, DepotDownloaderMod.

In this section

  • Prerequisites
  • Step 1: building DepotDownloaderMod
  • Step 2: building the Tauri app
  • Step 3: project structure

Prerequisites #

  • Rust, latest stable, and Cargo. Install via rustup
  • Tauri CLI, installed via Cargo

bash

cargo install tauri-cli
  • .NET 9.0 Desktop Runtime, required to run the embedded DepotDownloaderMod. Download the .NET 9.0 Desktop Runtime

Linux additional dependencies #

bash

# Debian/Ubuntu
sudo apt install libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf

# Arch/CachyOS
sudo pacman -S webkit2gtk-4.1 libappindicator-gtk3 librsvg patchelf

Step 1: building DepotDownloaderMod, optional #

The project embeds DepotDownloaderMod binaries at compile time. Pre-built versions are already included in the repository, so this step is only needed if you want to build them yourself.

Note

Pre-built binaries are located in DepotDownloaderMod-Windows/, which is framework dependent and requires the .NET runtime, and DepotDownloaderMod-linux-full/, which is self contained and needs no runtime. You can skip this step if you do not need to modify them.

Source: github.com/SteamAutoCracks/DepotDownloaderMod

Windows, framework dependent #

bash

git clone https://github.com/SteamAutoCracks/DepotDownloaderMod.git
cd DepotDownloaderMod
dotnet publish -c Release -o ./publish-windows

Then copy all files from publish-windows/ to DepotDownloaderMod-Windows/ in the project:

  • DepotDownloaderMod.exe
  • DepotDownloaderMod.dll
  • DepotDownloaderMod.deps.json
  • DepotDownloaderMod.runtimeconfig.json
  • SteamKit2.dll
  • protobuf-net.Core.dll
  • protobuf-net.dll
  • QRCoder.dll
  • System.IO.Hashing.dll
  • ZstdSharp.dll

Linux, self contained, no trimming #

bash

git clone https://github.com/SteamAutoCracks/DepotDownloaderMod.git
cd DepotDownloaderMod
dotnet publish -c Release -r linux-x64 --self-contained true \
    -p:PublishSingleFile=true -o ./publish-linux

Important

Do not use -p:PublishTrimmed=true. .NET trimming removes reflection metadata needed by SteamKit2 and protobuf-net, which causes "A task was canceled" errors at runtime.

Then copy publish-linux/DepotDownloaderMod to DepotDownloaderMod-linux-full/DepotDownloaderMod in the project.

Step 2: building the Tauri app #

Windows #

bash

cargo tauri build

Output locations:

  • nsis The installer lands in src-tauri/target/release/bundle/nsis/
  • portable The portable executable is src-tauri/target/release/steam-manifest-downloader.exe

Linux, Arch, CachyOS and similar #

bash

NO_STRIP=true APPIMAGE_EXTRACT_AND_RUN=1 cargo tauri build

Output: src-tauri/target/release/bundle/appimage/Steam Manifest Downloader_<version>_amd64.AppImage

Tip

NO_STRIP=true prevents stripping symbols from the embedded .NET binary. APPIMAGE_EXTRACT_AND_RUN=1 is needed on some distributions for the AppImage bundler to work correctly.

Step 3: project structure, for reference #

The include_bytes! macro in src-tauri/src/services/embedded_tools.rs embeds the DDM binaries at compile time:

  • windows The Windows build reads from DepotDownloaderMod-Windows/
  • linux The Linux build reads from DepotDownloaderMod-linux-full/

Careful

The DDM binary files must be in place before you run cargo tauri build. The Rust compiler reads them via include_bytes! at compile time, so if the files are missing, the build fails.

07 Help

eleven answers

Troubleshooting and FAQ #

Common issues and how to resolve them.

".NET not found" error on launch

The embedded DepotDownloaderMod requires the .NET 9.0 Desktop Runtime. Direct installer: .NET 9.0.16 Desktop Runtime, Windows x64. After installing, restart SMD and the warning banner should disappear automatically.

"Connection timeout" during download

This usually happens when the number of open connections overwhelms your network, or when Steam servers are under heavy load. Check whether a VPN or proxy is interfering with the connection. The app uses -max-downloads 8 by default, which works well for most connections.

Download stuck at 0%

First, check your internet connection. If your connection is fine, make sure your firewall or antivirus is not blocking DepotDownloaderMod.exe. You may need to add an exception for the application. Also verify that the .NET 9.0 Desktop Runtime is properly installed.

Linux: the AppImage will not launch

AppImages require FUSE to run. If FUSE is not available on your system, set the environment variable before launching:

APPIMAGE_EXTRACT_AND_RUN=1 ./SteamManifestDownloader_*.AppImage

Also make sure the file is executable: chmod +x SteamManifestDownloader_*.AppImage

No manifests found for my game

Not all games have manifests available in the searched sources. Make sure your .lua or .st file contains the correct depot and manifest IDs. You can also try adding a ManifestHub API key on the download page for access to additional sources.

The app crashes or shows a white screen

On Windows, make sure the Microsoft Edge WebView2 Runtime is installed. It is included with Windows 10 1803 and later and with Windows 11. On Linux, make sure WebKit2GTK is installed, with sudo apt install libwebkit2gtk-4.1-0 on Debian and Ubuntu.

Step 5 says "Removing DRM" but Steamless fails on Linux

Steamless is a .NET Framework 4.5.2 tool, so on Linux it needs mono. Install it via your package manager: sudo pacman -S mono on Arch, or sudo apt install mono-runtime on Debian and Ubuntu. After that, retry the DRM removal. SMD passes MONO_PATH automatically so Steamless's plugin assemblies resolve.

The patched game still refuses to start, gbe_fork applied but the game checks the API DLL

Some games verify the size or hash of steam_api*.dll at runtime and reject the gbe_fork swap. Open step 5 again via history, choose Edit emulator settings, scroll up and enable the Steam API check bypass toggle, then click Save. This installs the version.dll, winmm.dll and winhttp.dll hijacks next to game.exe, plus a SteamAPICheckBypass.json that redirects integrity check reads to the original .steam.bak.

Linux: "Add to Steam" added the game but no banner or hero is showing

Steam only re-reads shortcuts.vdf and the grid/ folder on a full restart. Closing the window is not enough: right click the Steam tray icon, choose Exit, then start Steam again. If the game has no Linux build, also right click the new entry in Steam, open Properties, then Compatibility, then enable a Proton version.

Edit emulator settings says "Folder not found"

The game folder was moved or deleted after SMD recorded it in history. Restore the folder or remove the history entry, which leaves disk files untouched. For partial cleanups, the history modal's confirm dialogs make destructive actions explicit.

No depot tags, Windows, Linux or 64-bit, appear in step 2

The tags come from api.steamcmd.net. If that service is rate limited or down, the request fails silently and the tags do not appear, and the rest of the interface is unaffected. Results are cached for 7 days in $APP_DATA/depot_info_cache/, so once they appear they stick.
