    Game data

    Game data for gbe_fork

    Writes what gbe_fork needs into steam_settings: languages, depots, branches, achievements with icons, leaderboards, inventory items and cloud save folders. With a Steam Web API key also the stats and all achievements. The controller layout has its own tab.

    Optional. Get a free key at steamcommunity.com/dev/apikey. It stays on this PC and is only sent to Steam.

    Save media

    Artwork, screenshots and inventory icons go into a steam_media folder in the game folder. The game does not need them.

    Tip: Achievement Watcher Next shows a notification when you unlock an achievement in an emulated game (Windows and Linux). It continues the original Achievement Watcher, which is no longer developed.

    Controller (Steam Input)

    Controller support

    Writes the game's Steam Input layout into steam_settings/controller, with button icons, so games that read the controller through Steam get input. This happens automatically when you patch or save, there is nothing else to press.

    Layout file

    Optional. A Steam Input layout (.vdf) that replaces the one from Steam, for example from your Steam folder under steamapps/workshop/content/241100.

    Which controller gbe_fork reports to the game. Games show matching button icons.

    gbe_fork only understands Xbox (XInput) controllers. Other controllers need Steam Input through Steam (below) or a tool like DS4Windows.

    Steam Input through Steam

    Only for PlayStation, Switch and other non-Xbox controllers, leave it off with an Xbox controller. It adds to the layout above, it does not replace it: Steam turns your controller into an Xbox controller, and gbe_fork uses the layout. For this, add the game to Steam in step 4 and start it from there.

    Help improve the app?

    We'd like to collect anonymous usage statistics so we know which features to invest in.

    We collect

    • App version, OS, architecture
    • Which features get used (counters only)
    • A random install ID (not tied to you)
    • Why a download failed — which step and what kind of error, from a fixed list of labels
    • With "Allow everything": how you move through the app, so we see where it gets stuck

    We never collect

    • Game IDs, depot IDs, file names
    • Contents of .lua / .st files
    • IP addresses, account info
    • Your manifest source URLs — only the kind of source, never the address

    Events are end-to-end encrypted with a public key embedded in the app — only the maintainer's server can decrypt them. You can change your choice anytime in Settings → Advanced Settings.

    Show us where the app gets stuck?

    You already share anonymous usage statistics. Would you also let SMD record how you move through the app?

    We collect

    • Which screens and steps you open, and how long you stay
    • Which buttons you click, by their internal name
    • Clicks on things that are not clickable, and repeated clicks where nothing happens
    • Long pauses, going back and forth, and opened hints

    We never collect

    • What you type, game names, IDs or paths
    • Screen contents or mouse positions

    Encrypted like everything else. You can switch it off anytime under Settings → Privacy & diagnostics.
